3. **Project goal clarification — the bulk of this session.** Worked through what "transmit the
   equivalent of 2PB using ~45KB" actually requires, across several passes:
   - Initial framing was: search a deterministic generator's output for an exact byte match, transmit
     only the found coordinate. Established this can't scale — search cost grows exponentially with
     target length against a structureless generator, which the 2026-08-03 session had already shown in
     miniature (a 2-byte target took 6,299 attempts).
   - Established the hard boundary underneath that: a primer of a given size can only ever address as
     many distinct outcomes as its own information content allows (2^N for an N-bit primer). This holds
     regardless of compute power — including quantum compute, and including arbitrary receive-side
     compute time (years/decades) — because it's a counting fact about how many distinct messages exist,
     not an engineering limitation that better algorithms or more time can route around.
   - Clarified the actual intent behind the project through a thought experiment: two supercomputers at
     opposite ends of a galaxy, sharing repositories of constants (π computed to extreme precision,
     physical constants, and combinations of them) that are generated independently and identically on
     both sides rather than transmitted. The sender searches locally for a starting point, a
     direction/path, and a primer; the receiver computes — potentially for years or decades — to
     reproduce the same result.
   - Resolved the apparent conflict between "the data we transport is anything and everything"
     (arbitrary) and the information bound by treating 45KB as the *target the research is discovering
     the real size of*, not a fixed proof — primer size is allowed to scale with what the actual target
     data requires, rather than being fixed in advance.

4. **Documentation restructure.** Split the single `SPEC.md` into three cross-linked documents so the

   - `INTENT.md` (new) — the *why*: Goal, Motivating scenario (the galaxy thought experiment), and

## Key decision / finding

The project's real constraint isn't an engineering gap to be closed with cleverer code — it's
information-theoretic: a primer can only ever address as much data as its own information content
allows, independent of compute power or time. This means the scheme can only work for target data that
has genuine low complexity relative to the shared repositories (real structure, redundancy, or an actual
short generating formula) — not for arbitrary/generic data. This is now documented in `INTENT.md`'s
"Known constraint" as a settled boundary, not an open question, since it's not something further
research or more compute could overturn.
